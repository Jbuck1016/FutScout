# FutScout production site audit — 30 September 2026

Scope: live `https://futscout.xyz` at production commit `f0115b1`, inspected in light and dark modes at a 1280×720 browser viewport. The review covered home/search, match analysis, players (profile, chain roles, rank, scatter, scout, compare, plot studio), teams, insights, sequences, player search, market values, forecasts/archive, Model Lab, Writing Lab, Quick Ingest, guide, glossary, methodology, and validation. I followed real links and exercised filters and drilldowns. I did **not** submit a scrape, publish content, or alter operational data. This is a browser/product audit, not a full data reconciliation or accessibility certification.

## What shipped before this audit

The production change removes the redundant top-level Chain Roles player tab and makes the profile's Chain Roles group display the actual role values and comparable players. It improves Scout text/number hierarchy, light-mode semantic colors, plot-event count truthfulness, Plot Studio color separation, the clipped `ATTACKING` label, and equal sizing for `Go to` and adjacent controls. The production deployment is Vercel `dpl_7DaQsa1wKSXbHGotswuQsTF9qwH1`. The [r/sportsanalytics research note](SPORTSANALYTICS_SUBREDDIT_REVIEW_2026-09-30.md) records further ideas; these are proposals, not claims of deployed features.

## Fix first — verified defects

### 1. Match Analysis route/filter state is inconsistent (P0)

From [home](https://futscout.xyz/index.html), search `Arsenal` and click the Brighton 3–0 Arsenal result, which opens [match.html?game=fd-560586](https://futscout.xyz/match.html?game=fd-560586). The match report correctly shows the Premier League fixture and its event snapshot (17–11 shots and 1.72–1.09 xG), but the left competition filter still has **Major League Soccer** checked, the team selector has no valid selected team, the match selector is empty, and the header says **0 played matches**. The facts on the report and the navigation context disagree. Resolve the match's competition and teams from its canonical ID before applying persisted/default filters; select the matching competition automatically and assert that the selected match belongs to the visible filter set.

Changing competition independently also resets `All teams` to the first concrete team. Repro on [match.html](https://futscout.xyz/match.html): with `All teams`, select MLS and Premier League, then uncheck MLS. The team selector silently becomes Arsenal and the counter falls to **5 played matches**, even though the Premier League has **50**. Preserve the sentinel `All teams` value across option rebuilds; add a regression test for league toggle → team filter → match list.

### 2. Player metric drilldown leaks filter and player state (P1)

On [players.html](https://futscout.xyz/players.html), filter Plot Studio to one player's fixture, then navigate to Rank and open another player's metric. The modal's fixture selector says `All fixtures` but its event view can show `0 of 919 source records` (Declan Rice progressive passes) or `0 of 1,077` (Jan Paul van Hecke) because a stale fixture ID from the prior player is still applied. Clearing the fixture in the modal can switch the drilldown subject back to the previously selected player. Reopening Rice after the reset displays 28 actions. Keep drilldown player and filters as modal-local state; when switching subjects, validate the fixture ID against that subject's fixtures and reset it if invalid. Automated test should traverse Plot Studio → Rank → another player → clear fixture and assert both subject and counts remain consistent.

### 3. Sequence similarity intermittently returns a server error (P1)

On [sequences.html](https://futscout.xyz/sequences.html), selecting a top chain for San Jose–Portland or Minnesota–New England initially returned `similar_sequences 500`; the selected pitch rendered but the nearest-neighbor area said `0 most similar`. The page shows an explicit retry error, which is good. Retrying Minnesota–New England **did** recover and return 12 nearest sequences, so this is intermittent rather than a permanent missing-data defect. Inspect RPC/database logs, query duration and query plan for the failed attempts; add a bounded retry/backoff if transient and an integration test. Do not infer “no similar chains” from an RPC error. The browse heading also runs together as “Produces a shotranked by xT”; fix the copy/spacing.

### 4. Generated scouting copy reverses PPDA's meaning (P1)

On [insights.html](https://futscout.xyz/insights.html), an MLS “New York break at speed from deep” read labels PPDA **8.64** a “passive press” and claims it invites pressure. Lower PPDA ordinarily means more frequent defensive actions per opponent pass, so the copy conflicts with its own metric. The detector text is hard-coded in `supabase/migrations/20260824025224_detector_denominator_gates.sql` for the counterattack class, without a PPDA or possession condition. Separate evidence-backed counterattack observations from unsupported press/low-block claims; condition any press description on the correct threshold, regenerate affected reads, and test that low and high PPDA cannot receive the same prose.

### 5. Match pitch cards collapse to unreadable strips (P1)

The default two-card layout on [match.html?game=fd-560586](https://futscout.xyz/match.html?game=fd-560586) shows Progressive Passes and Pass Map as approximately 50-pixel-tall pitch strips at 1280×720, leaving event marks illegible. The San Jose–Portland report showed the same behavior. The current static dashboard contracts pass, including four-slot pitch-height assertions; they do not catch this real two-slot browser rendering. Maintain pitch aspect ratio and a meaningful minimum card height; stack cards or allow one full-size primary pitch at this viewport. Add screenshot/dimension assertions for light and dark modes and 1/2/3/4 plot slots.

## Next — truthfulness and comprehension

### 6. Model Lab contradicts itself about rich-feature readiness (P1)

[Model Lab → Compare models](https://futscout.xyz/model-lab.html?tab=validation) says chance quality, xT and possession sequences are “coverage blocked” and cannot be tested fairly yet. [Model Lab → Challenger desk](https://futscout.xyz/model-lab.html?tab=research) says those same three families are “trainable now,” with **0** league-season blocks needing repair. These apparently describe different artifact dates, but the page presents both as present-tense conclusions. Put an artifact timestamp, coverage snapshot ID and test cutoff on every panel; retire or relabel the obsolete blockade. Likewise the Lab header says **46** scored calls while Trust tests' “External and live proof” says **44**. If one panel is older, label that explicitly rather than appearing to disagree about a live count.

### 7. Forecasts understate their own uncertainty caveat (P1)

[Model Lab → Data health](https://futscout.xyz/model-lab.html?tab=monitoring) reports `block_and_investigate` drift at 250 current matches, including severe rest-day and Elo drift. Trust tests show only **71.9%** historical final-position coverage for a nominal **80%** position set at the 25%-season checkpoint. Yet [Domestic forecasts](https://futscout.xyz/model-review.html) presents precise early-season title percentages (for example Bayern **98.7%** after four matches) without surfacing those caveats next to the table. This does not prove the table simulation is wrong, but it is a credibility risk. Link the table directly to calibration status; show simulation intervals for final points/position and a short early-season uncertainty warning.

Individual “Why this forecast?” cards show only last-three context beside contribution directions computed from standardized 3/5/10 windows. For Dortmund–Werder, the visible last-three field tilt, shots and box entries favor Werder numerically, while their attributed contribution favors Dortmund. Arsenal–Leeds shows 21 vs 20 rest days yet calls rest a moderate Leeds advantage. These *may* be valid model associations, but the current display invites a calculation-error reading. Model Lab's **Explain a match** already shows signed goal-balance contributions for the older 9/17 slate; reuse that pattern on the current forecast card, then add all contributing windows and flag counterintuitive directions. Distinguish model association from a football claim. For a resolved frozen call such as Brighton–Arsenal (35.2/24.2/40.5 forecast, actual 3–0), the dissection should also show the actual result, that call's score/log loss, and a link to the completed match report, clearly separated from the *pre-match* evidence. In the season table, Arsenal's **79.2** model final is 12 points already won plus **67.2** simulated from 33 remaining fixtures, versus **91.2** simple current pace. Expose this decomposition in an inspectable schedule view rather than asking users to infer it.

### 8. Reference copy contains factual and scope contradictions (P1/P2)

[Field guide](https://futscout.xyz/guide.html) says 2,916 players touched the ball and 2,915 were named in a squad, “including 0 unused substitutes,” then says the difference is exactly that number. The arithmetic is self-contradictory. It also describes “roughly 17 games per side” as if current for all six leagues; MLS has a much later season phase. The guide's fixed quiz score badge overlaps reading text at this viewport. [Validation](https://futscout.xyz/validation.html) calls xG the platform's “one fitted model,” although the site also has a separate V2 match model; make clear it means one fitted **shot-quality** model or update the page. [Methodology](https://futscout.xyz/methodology.html) promises “every formula, threshold and modelling choice” but contains no Elo, Poisson or domestic forecast-model section at all. Either include the forecast method and artifact lineage there or narrow the scope claim and link prominently to Model Lab. [Glossary](https://futscout.xyz/glossary.html?m=xg_per_shot) has no named competition on its example distribution despite six leagues. A periodic docs-to-current-data contract would catch these.

### 9. Navigation still clips at 1280 pixels (P2)

The global `Go to` menu is comprehensive and now matches the export-button height. But the [Players](https://futscout.xyz/players.html) and [Teams](https://futscout.xyz/teams.html) inner-tab rows lose tabs under or behind the right control cluster at 1280px. When the active player tab is Compare or Plot Studio, earlier tabs are out of view with no obvious overflow cue. Use a second-row/tab scroll control or shorten the header, and test 1024/1280/1440 viewport widths. This is not just cosmetic; hidden navigation makes the new single-location Chain Roles harder to discover.

### 10. Empty states and labels imply the wrong scope (P2)

[Scouting insights](https://futscout.xyz/insights.html) opens on Premier League with zero reads because its detector has a six-match threshold, while the homepage advertises 1,034 reads across leagues; default to a league with data or clearly guide users to MLS. [Writing Lab](https://futscout.xyz/writing-lab.html) now offers domestic leagues and Europe, but its blank-state copy still says the scraper “will isolate the cup data.” Player Scout says “Every number ... is a percentile,” despite raw per-90 value and 90s columns. Player profiles show the internal token `Fit confidence: low_sample`; translate it into plain language with threshold. [Player search](https://futscout.xyz/search.html) lists nominal formation positions such as AMC/AMR for results in an inferred striker role pool; label the two fields separately so a valid result does not look like a filter error.

### 11. Form semantics and visual marks need a targeted accessibility pass (P2)

Browser accessibility snapshots show several unlabeled comboboxes on Players, Match Analysis and Insights: adjacent visible text such as “Role pool” or “Competition” does not consistently become the control's accessible name. Give every select, filter and minute input an explicit label and test keyboard traversal/focus. In Plot Studio's light mode, the updated semantic palette is much clearer, but point categories still require both shape and visible label in exports, not color alone. This audit did not perform a full assistive-technology or WCAG contrast measurement.

## Design and analytical direction

Several flows deserve to be kept: home search finds Arsenal and links to the correct Brighton–Arsenal report; the report's event counts and shot-xG coverage are explicit; the homepage league selection carries through to Player Fingerprints; the profile's one Chain Roles group now has real values; Scout provides raw metric values alongside percentiles; the Plot Studio supports a mixed-category pizza and configurable event filters; the sequence overlay works after the similarity retry; the Market desk clearly warns that Bundesliga and MLS valuations are missing; and Model Lab's Trust tests distinguish a small historical lift from a statistically defensible winner. Preserve these when reworking the interface.

The new player profile/Scout panels are substantially better than the former pale microtype: primary numbers, names and score bands are readable in light and dark modes. Plot Studio's action counts and glyph classes now describe the selected source actions; the `ATTACKING` label is fully visible, and the light-mode event colors are stronger. Pattern mode represents 17 actions in a smaller number of aggregated flows, so say “17 actions represented” rather than “17 distinct actions plotted” there. Its pitch occupies only about 360 pixels of a much wider card; enlarge it or use the spare width for a useful legend/evidence sidebar. The site still feels like multiple visual systems: editorial landing/Writing Lab/Market desk, dark dense Match Analysis, and small monospaced Insights/Search/Guide. The next visual pass should establish one shared type scale, line-height, minimum contrast, semantic color map, chart minimum size, and legend pattern. Apply it to real task flows, not to screenshot decoration.

Borrow the useful *method* from the subreddit review: lead a match with one question and three to five inspectable pieces of evidence, pair pizzas with sortable role-relative numbers and sample size, show pass-versus-carry xT with grid/version/coverage, and compare tactical models on identical frozen fixtures with per-league uncertainty. Do not copy a graphic without the data contracts or imply event-location heatmaps are optical tracking.

## Verification boundary and recommended order

I verified the live deployment and navigated the site, but did not test mobile widths, every export download, screen-reader output, every team/fixture, the authenticated scrape submission, or database/API logs for the similarity error. Those need separate targeted checks. Prioritize: **(1)** Match Analysis context/filter and pitch geometry; **(2)** player drilldown state and sequence RPC; **(3)** misleading generated copy and artifact freshness; **(4)** calibration warnings/reference-copy correctness; **(5)** navigation/type-system pass and question-led evidence design.
